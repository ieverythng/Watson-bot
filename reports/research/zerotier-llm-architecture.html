🔑 Key Design Decisions

Why LiteLLM on Windows?

LiteLLM is a proxy layer, not an inference engine. It sits between clients and the model server, translating API formats and managing routing. By placing it on the Windows PC alongside llama.cpp:

  • Single configuration point — configure once, all devices connect
  • ZeroTier binding — LiteLLM binds to 0.0.0.0, exposing port 4000 on the ZeroTier interface
  • Responses API translation — Codex CLI/App uses OpenAI's Responses API; LiteLLM translates it to Chat Completions that llama.cpp understands
  • No duplicate installs — Mac and Linux only need Codex CLI/App, no proxy software

Why llama.cpp binds to localhost?

llama.cpp stays on 127.0.0.1:8080 — it's the raw inference engine and doesn't need external exposure. LiteLLM handles all network-facing concerns:

  • Authentication & rate limiting
  • API format translation (Responses ↔ Chat Completions)
  • Request queuing when multiple clients connect simultaneously

📋 Implementation Steps

Step 1: Install LiteLLM on Windows PC

# On Windows PC (PowerShell or CMD)
pip install 'litellm[proxy]'

# Verify installation
litellm --version

Step 2: Create LiteLLM Config File

Create C:\Users\Juan\.litellm\config.yaml:

# litellm-config.yaml
model_list:
  - model_name: qwen36-turbo-hermes
    litellm_params:
      model: openai/qwen36-turbo-hermes
      api_base: http://127.0.0.1:8080/v1
      api_key: placeholder

env_vars:
  OPENAI_API_KEY: placeholder

Step 3: Ensure llama.cpp Binds to ZeroTier

Your llama.cpp server on Windows needs to be accessible. Check that it binds beyond localhost:

# In your llama.cpp startup command, ensure --host is set to 0.0.0.0 or omitted
# Default llama.cpp server command:
llama-server -m path/to/model.gguf --port 8080 --host 0.0.0.0 --ctx-size 32768

TODO Verify your current llama.cpp startup binds to 0.0.0.0, not just 127.0.0.1. If it only binds to localhost, LiteLLM on the same machine can still reach it via 127.0.0.1.

Step 4: Start LiteLLM Proxy

# On Windows PC (PowerShell)
$env:OPENAI_API_KEY = "placeholder"
litellm --config C:\Users\Juan\.litellm\config.yaml --port 4000 --host 0.0.0.0

This binds LiteLLM to 0.0.0.0:4000, making it accessible via ZeroTier at http://172.24.16.1:4000.

Step 5: Configure Codex on Linux/Mac

Create ~/.codex/config.toml on each client machine:

# ~/.codex/config.toml
[openai]
base_url = "http://172.24.16.1:4000/v1"
api_key = "placeholder"

Then test:

codex exec --model qwen36-turbo-hermes "Say hello"

Step 6: Codex Desktop App (Optional)

For the desktop app, run codex app-server on Linux/Mac pointing to the proxy:

# On Linux laptop
codex app-server --listen ws://0.0.0.0:8081

# On Mac, open Codex App and connect to:
# ws://<linux_zerotier_ip>:8081

🔧 Service Management (Windows)

Option A: Windows Task Scheduler

Create a scheduled task that runs on login:

# PowerShell script: start-litellm.ps1
$env:OPENAI_API_KEY = "placeholder"
& litellm --config "$env:USERPROFILE\.litellm\config.yaml" --port 4000 --host 0.0.0.0

Option B: Windows Service (nssm)

# Install nssm: choco install nssm
nssm install LiteLLMProxy "litellm" "--config %USERPROFILE%\.litellm\config.yaml --port 4000 --host 0.0.0.0"
nssm set LiteLLMProxy AppEnvironmentExtra "OPENAI_API_KEY=placeholder"
nssm start LiteLLMProxy

🚨 Known Issues & Mitigations

Chat Completions Auth Quirk: LiteLLM proxy sometimes fails to pass credentials through to llama.cpp for /v1/chat/completions. The /v1/responses endpoint works cleanly. Workaround: set OPENAI_API_KEY as an environment variable when starting the proxy process.
Concurrent Request Latency: llama.cpp processes requests sequentially. When Hermes and Codex both send requests, they queue. Expect 10-30s latency per request for a 26B model. Don't run heavy tasks simultaneously.
Image Support Requires Vision Bridge: llama.cpp does not support image input. To use images with Codex CLI, run the Vision Bridge on Linux (port 8002) and point Codex at it (openai_base_url = "http://127.0.0.1:8002/v1"). Without the bridge, images cause Codex to disconnect/reconnect with "image input not supported". See reports/research/zerotier-llm-bootstrap.html for setup instructions.

📊 Token Budget Notes

Context Window: Your model has n_ctx: 65536 tokens. Codex sessions can be long — monitor context usage. Consider setting --ctx-size 32768 or 65536 in llama.cpp startup for adequate context.
