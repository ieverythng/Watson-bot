# Skill: memory-reflector

## Purpose
Condense observations into stable patterns and promote only durable truths.

## When to Use
- Session end
- Milestone reached
- Observation log becomes noisy/redundant
- Project direction changes

## Required Inputs
- Observation window
- Candidate durable updates
- Evidence references

## Steps
1. Review recent `OBSERVATIONS.md` entries and daily memory logs.
2. Identify durable themes and unresolved conflicts.
3. Append/update reflection in `REFLECTIONS.md`.
4. Promote only high-confidence facts to `MEMORY.md` when justified.

## Expected Output
- Reflection entry with themes/actions/evidence
- Optional memory promotion with provenance

## Failure Handling
- If contradictions exist, record conflict and defer promotion.

## Example
- Theme: staged-first workflow improves reliability
- Action: maintain staged review gate before commits
